# ADR 0001: 全体アーキテクチャ

- 状態: 採用
- 日付: 2026-11-21

## 背景

Go + Wails v3 で、タブ・入れ子ペイン・複数ウィンドウ・差分表示を持つ Markdown ビューアーを作る。
後から変更すると作り直しになる判断をここに記録する。

## 決定

1. **フロントエンドは Vanilla TypeScript + Vite**（フレームワークなし）。
   - ユーザー CSS でのカスタマイズを前提に、DOM 構造とクラス名を完全に制御するため。
2. **Markdown のレンダリングは Go 側（goldmark）**。
   - 見出し抽出・差分計算・ローカルリンク/画像の解決を Go に一元化し、Go でテストする。
   - シンタックスハイライトも Go 側（chroma, CSS クラス出力）で行い、配色は CSS で切り替える。
   - Mermaid は Go 側で `<div class="mdv-mermaid">` としてソースを出力し、フロントで pele により SVG 化する。
3. **ペインは入れ子分割ツリー**（VS Code のエディターグループ風）。各ペインがタブバーを持つ。
   レイアウト状態はウィンドウごとにフロントエンドが保持する。
4. **単一プロセス・複数ウィンドウ**。ドキュメント（ファイル内容・基準内容・監視）と
   ワークスペース（開いたファイル/フォルダー一覧）は Go 側で一元管理し、全ウィンドウで共有する。
   変更は Wails イベントで全ウィンドウへブロードキャストする。
5. **ウィンドウ間のタブ移動はスクリーン座標でルーティング**する。
   タブの `dragend` 時にポインタがウィンドウ外なら、Go がそのスクリーン座標（DIP）を含む
   他ウィンドウを探して移動し、無ければその位置に新規ウィンドウを作る。
   WebView 間の HTML5 D&D の可否に依存しないため、全 OS で同じ仕組みで動く。
6. **差分はトップレベルブロック単位**で計算する（基準ソースと現在ソースを goldmark で
   ブロックに分割し LCS）。追加ブロックは `mdv-diff-ins`、削除ブロックは基準側の HTML を
   `mdv-diff-del` で挿入する。
7. **ローカルファイル配信**はアセットサーバーのミドルウェアで `/_mdv/file/<絶対パス>` を提供し、
   画像などを表示する。
8. **クラス名は `mdv-` 接頭辞 + ハイフン区切りの階層**（例: `mdv-sidebar-files-item`）。
   状態は `is-active` などの汎用クラスで表す。深い BEM 修飾子は使わない。

## 影響

- Go 側に `internal/markdown`, `internal/diff`, `internal/workspace` などのパッケージを置き、単体テストする。
- フロントエンドは描画済み HTML を受け取り、後処理（Mermaid、コピー、リンク、検索ハイライト）のみ行う。
