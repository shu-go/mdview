# ADR 0003: テキストファイルの表示と文字コード

- 状態: 採用
- 日付: 2026-11-26

## 背景

Markdown 以外に、プレーンテキスト（メモ・ログなど）も同じ UI（タブ、差分、検索、監視）で見たい。
日本語環境では Shift_JIS のテキストも多い。

## 決定

1. **種類は拡張子で決める**（`internal/workspace` の `Kinds`、フロントは `filetypes.ts`）。
   - Markdown: `.md` `.markdown` のみ（以前の `.mdown` `.mkd` などは対象外にした）。
   - テキスト: 設定 `textExtensions`（既定 `txt`、空白区切り）。
   - それ以外は開かない（`unsupported file type` を表示）。フォルダーの走査・監視も同じ判定。
     文書内リンクから開く場合は従来どおり確認のうえ既定アプリ。
2. **テキストの描画は Go**: 空行区切りの段落を 1 ブロック（`p.mdv-text-block`、`white-space: pre-wrap`）にし、
   goldmark の AST に最上位ブロックとして並べる。これで既存のブロック差分・`data-line`・
   フロントの段落内差分・検索・スクロールバーのマークをそのまま使う。
   本文は全てエスケープし、http(s) URL だけリンクにする（Markdown と同じ linkify）。サニタイズも通す。
3. **長い段落の分割は内容で決める**: 16 行以上たまった後、行のハッシュが当たった行の後で切る（最大 64 行）。
   1 行の挿入で以降のチャンク境界が全部ずれることを避ける（影響は前後のチャンクに留まる）。
4. **文字コード自動判別**（`internal/textenc`、Markdown にも適用）: BOM（UTF-8 / UTF-16LE/BE）→
   妥当な UTF-8 → それ以外は Shift_JIS（CP932）。読み込み時に UTF-8 へ変換して保持する
   （差分・grep も変換後の文字列で行う）。NUL を含むファイルはバイナリとして拒否、32 MB 超も拒否。

## 結果

- コードブロック描画の流用（ファイル全体を 1 ブロック）は、差分・行ジャンプが効かないため採らなかった。
- EUC-JP などは判別しない（UTF-8 でなければ Shift_JIS とみなす）。
- 連続する複数の空行は 1 つの段落間隔として表示される。
